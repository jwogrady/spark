# Spark Alpha — feedback field reference

> **This is a read-ahead reference, not a submission form.** Do **not** copy it
> into an issue. The one canonical way to submit Alpha feedback is the
> **`alpha-feedback` GitHub issue form** (New Issue → *Alpha feedback*), backed
> by `.github/ISSUE_TEMPLATE/alpha-feedback.yml`. This page just lists, in plain
> language, what that form will ask — so you can think about a run before you
> open the form. See the [testing guide](testing-guide.md) for how to file.

## Before you file (the form enforces all of this)

- **Reports are public.** Anyone can read them.
- **Use your coordinator-assigned pseudonym** (e.g. `P1`). **Never** enter your
  real name or email.
- **No secrets or credentials.**
- **No proprietary or customer source code.**
- **No customer data or personal information** (yours or anyone's).
- **No sensitive recordings or screenshots.** Recordings, only when you've
  explicitly consented, are handled privately by the coordinator — never
  attached to an issue.

## What the form asks

The `alpha-feedback` form collects the fields below. Answer them there, not
here. Blanks are fine on the free-text fields — an honest blank is data.

- **Participant ID** — your pseudonym (e.g. `P1`), never a real identity.
- **Experience level** — newcomer to structured delivery / mid / strong engineer.
- **Which run** — 1st / 2nd / 3rd+.
- **Project type** — new project / existing repository.
- **Stack** — language and framework.
- **Unaided outcome** — did you reach a shipped PR with no coordinator/author
  help; if not, where it stopped.
- **Per-stage friction** — onboard/ideate/plan/codify/validate/ship, rated
  0 (frictionless) – 3 (blocked me), with why, and why you skipped any stage.
- **Stop-and-think moments** — every point you paused, backtracked, or asked
  "what does this do?" The most valuable field.
- **Discoverability** — which commands you found on your own vs only after being
  told; which names were unclear.
- **Documentation used** — which docs you opened, whether they answered you,
  which you never opened even when stuck.
- **Value** — did Spark save time, cost time, or break even; prevent a mistake;
  improve planning/quality; still worth it on a repeat run.
- **Keep or stop** — and one line: "I would keep/stop using Spark because …".
- **Anything else** — redesign ideas welcome, treated as hypotheses until a
  second participant corroborates.
