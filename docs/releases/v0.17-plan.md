## Shippable outcome

A Spark-managed spoke can remain lean while durable cross-project learning is deliberately promoted, with GitHub evidence and required human judgment, into one configured memory-hub repository.

The release is successful when the workflow works generically and is proven through Cosmos dogfood without making Cosmos a Spark dependency.

## Release proof

The outcome-completion criteria (historically framed as the bar for a `v0.17.0`
cut; now the bar #373 certifies):

1. A positive fixture demonstrates a durable boundary discovery being classified and promoted with evidence.
2. Negative fixtures demonstrate routine engineering work terminating with no hub write.
3. A real spoke-to-Cosmos dogfood run uses configured hub resolution and Cosmos's existing review/placement rules.
4. No Spark code or docs require Cosmos, Status26, Prime, or repository naming conventions.
5. The five public lifecycle stages remain unchanged.
6. `spark doctor` and relevant behavioral/evaluation tests are green.
