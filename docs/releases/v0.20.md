## The two authorities this release separates

The whole orchestration slice rests on refusing to collapse two questions that
look similar and are not:

| Question | Authority |
| --- | --- |
| What must be **true** before work can start? | GitHub's native `blocked-by` graph |
| Which eligible issue should be taken **first**? | The gate's native **sub-issue order** |

Collapsing them is what makes a backlog lie. An ordering preference encoded as
a `blocked-by` edge becomes a false blocker that fails readiness closed; a real
prerequisite demoted to "ordering" starts work too early. Free-form milestone
prose is never parsed by either surface — it explains the order, it does not
define it.

## Self-hosting evidence

v0.20 was executed **using released Spark `v0.19.0` as the operator**, against
this repository as the subject. The provenance of that operator was proven by
content, not by its version string — two artifacts have carried the name
`v0.19.0`, and the installed tree was shown byte-identical to the published tag
across 81 files, discriminating against both withdrawn artifacts.

Once #436 merged, **Spark selected its own remaining work**:

```
$ spark next
Spark next — milestone "v0.20 — Self-host Spark"

selected  #437
title     Route selected issues by category and approval boundary before Codify
priority  P1
eligible  yes
blocked   no
order     5 of 7 in the gate sub-issue order
reason    highest-priority eligible issue
```

Once #437 merged, that selection was **routed** by Spark rather than by
judgement:

```
issue     #437
category  feature
route     codify -> validate -> ship
approval  none
why       implementation work: the lane that writes code owns it
```

And with every leaf closed, the selector reported the end of the milestone as a
**known** answer rather than an unassessed one — exit `1`, not exit `3`:

```
$ spark next
no eligible issue: this milestone has no open leaf issues
```

That distinction is the release's smallest and most characteristic idea: a
known negative and an unknown are different facts, and a tool that confuses
them teaches its reader to distrust both. It is why #487 split a duplicate-only
release-notes result away from a blocking one, why #438 refuses to let prose
manufacture a blocker, and why #488 was filed against `resume` for committing
the same error in reverse.
