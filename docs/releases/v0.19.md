## Why this is the catch-up release

`master` already carried the cumulative implementation through this outcome when
the reconstruction ran. Cutting a fresh `v0.17.0` from that `HEAD` would have
placed v0.18 and v0.19 implementation inside a tag named `v0.17.0`, and reduced
`v0.18.0`/`v0.19.0` to governance-only releases — recreating the release/scope
mismatch the rollback had just corrected.

So v0.17 and v0.18 take `Complete (no release)`, and their implementation reaches
the public once, here. `master` is linear and was not rewritten, so the withdrawn
tag boundaries are evidence only — never version authority.

## The withdrawal was three different failures, not one

**This distinction must not be flattened.** The six withdrawn publications fail
in materially different ways.

### v0.17.0 — planning structure existed; certification was premature

| Artifact | Existed before publication |
| --- | --- |
| Milestone | #14, created 2026-08-12T19:50:07Z |
| Release-readiness gate | #373, created 2026-08-12T19:38:44Z |
| Roadmap entry | a `## v0.17` section in `ROADMAP.md` |
| Release plan | `v0.17-plan.md` (PR #378, commit `333b85bb`) |
| Issues | #372, #374–#377, #380, milestone-assigned |

`v0.17.0` published 2026-08-13T00:57:25Z, after all of it. The defect was the
boundary and its certification: #373 was closed as `completed` so release PR #382
could go green, and #389 proved three of the gate's own criteria were unmet. The
governance **existed and was overridden**.

### v0.18.x — publishing outran the planning structure

At `v0.18.0`'s publication (2026-08-25T01:27:31Z): **no milestone** (#15 created
2026-08-26T19:37:21Z), **no release-readiness gate** (#444 created
2026-08-26T19:39:17Z), **no roadmap section at all**, **no release record**.
Issue coverage was **partial** — the `v0.18.0` slice was issue-backed; the
`v0.18.1`/`v0.18.2` slices were not.

### v0.19.x — no planning structure and no issues

**No milestone** (#16 created 2026-08-26T19:37:55Z), **no release-readiness gate**
(#445 created 2026-08-26T19:40:18Z), **no roadmap section**, **no release
record**, and **no issues at all** — every PR merged directly. This is the
furthest departure: neither the issue layer nor the release-governance layer was
present.

## Withdrawal record

All six GitHub Releases and their tags were deleted on 2026-08-26. **`master`
history was preserved throughout**: no commit was removed, no pull request was
unmerged, no force-push and no rewrite. `master` stayed at
`6f9c0269d1334a572a43cb84227e63add1a6d6ab`, and all 115 commits and 37 merged
PRs since `v0.16.2` remain.

Companion releases were untouched: `spark-audit-v0.2.2`, `spark-connect-v0.2.2`,
and `spark-docs-v0.3.1` sit on the same commit as `v0.15.1`, predate the
`v0.16.2` baseline, and were never part of the withdrawn train.

`v0.16.2` became the published baseline again, and remained so until this release
was cut on 2026-08-26.
