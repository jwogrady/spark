## The two constraints, and where they were tested

**Unknown evidence is not human judgment.** Every verb carries them as separate
states, and a row whose evidence is unread carries no disposition at all.
Asserted directly in `test-triage-truth.sh`, `test-reconcile-slate.sh` and
`test-course-derivation.sh`, each with a negative control proving the collapse
would be caught.

**Recommendation is not authority.** An agent may propose a value with evidence;
the gap clears only when the governed field carries the decision. Asserted in
`test-governance-decision.sh` with the #558 incident as a three-state fixture,
and re-proved live during certification.

### Why the gates did not catch it

Issue-level `docs-impact` (#483) proves that **the documentation classes an issue
declared** were satisfied. It cannot prove the **declaration itself was
semantically complete**. Every v0.22 issue declared truthfully against the
surfaces it named, and no issue named the README — so every check passed and the
public description of the product still described v0.21.

That is the gap, stated as the canonical fixture:

```text
Given:
  a release introduces a new public product capability
  reference/operator docs correctly describe it
  all declared docs-impact evidence passes
  README/public positioning still describes the previous product

Then:
  docs-truth = FAIL
  release readiness = NOT READY
```

### What v0.23 owes because of it

Two checks, not one — issue-level `docs-impact` evidence **and** release-level
semantic `docs-truth` (#484). #484 is the release-level backstop and lands early
enough in v0.23 to govern the rest of it. `tests/test-readme-product-truth.sh`
guards this specific regression in the meantime; it is a regression guard, not
the `docs-truth` surface #484 builds.

Documentation is evidence of current meaning and intended behavior. It does not
override stronger mechanical evidence, and it does not manufacture authority it
does not own.
