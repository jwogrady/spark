# v0.23 usage and field-evidence report

> **Status:** In progress — v0.23 is **not released**. The release gate
> [#480](https://github.com/jwogrady/spark/issues/480) is open and closes last;
> final release approval is human-owned. This report is the durable
> release-evidence deliverable required by
> [#709](https://github.com/jwogrady/spark/issues/709); it records evidence, it
> does not certify the release.

## Purpose

Before v0.23 ships, this report gathers — in one pointable place — where Spark
has actually been used, what it materially contributed, which released control
plane governed the work when that is provable, what was measured, and where
Spark failed or got in the way. Every material claim links to durable
GitHub/repository evidence so a reader can verify it cold rather than
reconstructing it from dozens of objects.

It is deliberately **not** a success story. Released-v0.22 consumer usage is kept
separate from unreleased-v0.23 self-host dogfood; governor provenance is kept
separate from execution provenance; consumer outcomes are kept separate from
Spark's contribution (correlation is not attribution); and failures, friction,
and `NOT ASSESSED` gaps are preserved alongside the wins.

## Reporting vocabulary

```text
Governor   = released Spark vX.Y.Z control plane that actually governed the work
Execution  = role/model/provider/surface/run facts proven by durable evidence
Work unit  = repository + issue/PR/run/HEAD being described
Outcome    = observed result/verdict, not authority
```

**Governor evidence class** is one of:

- **CANONICAL** — a #710 `Spark-Governed-By: vX.Y.Z` commit trailer / durable
  PR-level governor fact, sourced from the installed released governor.
- **HISTORICALLY EVIDENCED** — the released governor is established by
  independent durable evidence (dates, release windows, attested prose), but
  predates #710 so no canonical trailer exists.
- **NOT ASSESSED** — the released governor cannot be mechanically established;
  reported as unknown, never fabricated.

The governor is **never** inferred from the target repo's working-tree version,
the release being developed, Spark files merely being present, an installed
integration alone, provider/model identity, or conversation memory. No
historical commit or PR is rewritten and no retroactive governor metadata is
fabricated. The pre-#710 absence of canonical governor provenance is itself
legitimate negative evidence.

**Governor timing anchor:** released **v0.22.0** was published
**2026-08-30T14:25:41Z** (tag `v0.22.0`, target commit `f364d42`,
[release](https://github.com/jwogrady/spark/releases/tag/v0.22.0)). The #710
canonical governor primitive did not exist until PR
[#712](https://github.com/jwogrady/spark/pull/712) merged
**2026-09-03T19:13:47Z** (`8a49ed5`). Every work unit below therefore predates
the canonical-provenance install and is **HISTORICALLY EVIDENCED** or
**NOT ASSESSED**, never CANONICAL, on governor attribution — including the #710
PR itself, which carries `Governed by Spark v0.22.0` because the then-installed
governor was v0.22.

**What released Spark demonstrably contributed** (from #679, corroborated by the
#171 handoff — Spark's contribution, distinct from the consumer's design outcome):

- **Commit-message enforcement refused invalid commits, which were then
  corrected** — the installed commit-msg hook rejected an AI `Co-Authored-By`
  trailer the agent's own defaults tried to add, and subjects over the 72-char
  limit (including a later 74-character subject). The agent reported changing its
  commits because Spark refused them.
- **`spark state --set` failed atomically on invalid state** — rejected an
  invalid key rather than leaving a partial record.
- **`spark brief --short` prevented repeated rediscovery** of settled facts
  (release mode, stack, preference posture) across issues.
- **Governance vs execution authority stayed distinct under a long run** — v0.22
  governed while paid commissioned-media spend remained a human-owned Crossroad.

**Negative / friction evidence from the same engagement** (see the Defects
section for owners):

- **Guard false-positive** — `guard-bash.sh` blocked a legitimate feature-branch
  push because the same compound command also contained `gh pr create --base
  master`; the word `master` belonged to the PR-base argument, not the push
  refspec. Worked around by splitting the commands.
- **`spark next` unmilestoned-selection limitation** — `spark next → NOT ASSESSED`
  for the whole run because the consumer repo had no open milestone with open
  issues; the operator had to become the selection layer.
- **What Spark did not find** — the strongest quality findings (a copy-width rule
  colliding with a generated terminal, a missing vertical-overlap composition
  contract, an Astro selector-specificity defect, the zero-pixel tangency fixed
  by PR #175) came from rendered browser evidence and specialist review, **not
  Spark**. This is boundary evidence, not asserted as a Spark defect.

### Runtime-footprint telemetry truth (#670) — CANONICAL semantics

[#670](https://github.com/jwogrady/spark/issues/670) (CLOSED/COMPLETED, PR
[#717](https://github.com/jwogrady/spark/pull/717) merged `3a454e2`) corrected the
run-footprint telemetry so a multi-command run is truthful: each invocation
**appends** `<bytes>\t<modules-or-none>\t<iso8601>` to an append-only
`.spark/telemetry/<run>.footprint` log, and reads **derive** the summary —
`runtime_peak_source_bytes` (the peak single-invocation bytes, monotonic) and
`runtime_modules_loaded` (the distinct union of modules loaded). **Semantic
guard for this report:** these are a *run summary* (a peak and a set), **not**
richer per-actor or per-command execution provenance; they must not be
reinterpreted as such.

## What Spark demonstrably helped

- Enforced authorship/commit discipline that a working agent then complied with
  (commit-msg refusals; the preserved AI `Co-Authored-By` ban).
- Kept governance authority distinct from execution under a long real
  engagement, with paid spend remaining human-owned.
- Reduced rediscovery of settled project facts (`spark brief --short`).
- Exercised, in self-host, a genuine one-review-per-HEAD repair discipline where
  each new HEAD received fresh review (five of six merged HEADs carry a reviewer
  PASS).
- Landed two telemetry-truth corrections (#665 execution counts, #670 runtime
  footprint) and the canonical governor primitive (#710), each with green suites.

## What Spark demonstrably did not help / does not own

- Spark did **not** surface the consumer's substantive visual/design defects;
  rendered browser and specialist review did. Spark's contribution there was
  process discipline, not quality detection.
- The `spark next` selection layer did not function for an unmilestoned consumer
  repo; the human became the selection layer.
- A compound-command guard false-positive blocked legitimate work.
- No mechanically-emitted, provider-instrumented execution provenance
  (model/provider/tokens/cost) exists for the consumer engagement; that richer
  role/model/provider/surface provenance is #711 (v0.24), explicitly **not** a
  v0.23 dependency and not claimed here.

## Release conclusion against #480's measurement requirement

**#480's measurement criterion is NOT YET SATISFIED.** The record shows Spark's
optimization and governance primitives were genuinely exercised in the field
(released-v0.22 consumer usage) and in self-host (review cycles, telemetry-truth
corrections, the governor primitive), with failures and boundaries preserved. But
the specific gate claim — *representative measurements show material improvement in
at least two cost/latency/token/tool dimensions without reducing correctness* —
is **not supported by comparable evidence**: there is a single baseline and no
after-measurement, three of five representative workloads are NOT ASSESSED, and
the #480 acceptance checkbox for that claim remains unchecked.

Correctness evidence is strong (green suites, doctor healthy, honest reviewer
cycles). The efficiency-improvement claim is not yet evidenced. Per #480, this
report therefore leaves that gate criterion **unsatisfied** rather than inferring
improvement from missing comparisons. Closing it requires a comparable
before/after measurement pass across the representative workloads, ideally with
provider-instrumented execution telemetry, before final human-owned v0.23 release
approval.
