# v0.12 orchestration — recommendation & decision record

This is the #190 research epic's recommendation and the #198 decision-gate
record. It rests on two ratified ADRs and one measured baseline:

- [ADR-0023](../adr/0023-lifecycle-orchestration-topology.md) — the Shape / Build / Assure & Deliver topology (Accepted).
- [ADR-0024](../adr/0024-capability-based-model-selection.md) — capability-based model selection (Accepted).
- [`evaluations/orchestration/BASELINE.md`](../../evaluations/orchestration/BASELINE.md) — the current single-agent lifecycle measured on one fixture per group (research evidence, n=1, estimates labeled).

## The decision: research & architecture only

**v0.12 ships the ratified architecture and the measured baseline — no new
runtime orchestration capability.** The candidate first slice (#206, parallel
review roles) is **deferred**, not built, this milestone.

Why (from the baseline evidence):

| Group | Baseline | Reading |
| --- | --- | --- |
| **Build** (Codify) | 6/6 correctness, 0.88 quality | Clears the bar with no headroom — benefits *least* from multi-agent work. Keep it single-agent. |
| **Shape** (Ideate→Plan) | 5/7, 0.80 | Weakest group; the two misses (thin prior-art, premature solutioning) are exactly what parallel evidence/critique agents target — the **largest** opportunity. |
| **Assure & Deliver** (Validate→Ship) | 3/4, 0.88 | Caught the bug and the security defect; missed a project-specific standard. #206 is plausible here, but unproven. |

The milestone's own rule (#206's acceptance criteria) is that a slice must be
**measured against this baseline and beat it** before adoption. We do not yet
have that comparison, and building #206 blind would contradict the
evidence-first principle #198 is built on. So: ratify the durable architectural
decisions now; gate the build on evidence later.

## Where agents help (the ratified position)

- **Shape** — highest-value target for parallel evidence/constraint/critique
  helpers under a synthesis barrier (ADR-0023). Capability profile: deep
  reasoning + long-context (ADR-0024).
- **Assure & Deliver** — independent *native* reviewers (`/code-review`,
  `/security-review`, `verify`) over separable inputs, then a synthesis/fix
  loop. Capability: independent review + deep reasoning. This is the #206 slice.
- **Build** — stays single-agent; scoped helpers only for genuinely independent
  sub-tasks. Capability: code execution.

Human, Spark, Claude, and GitHub keep the ADR-0019 roles: agents gather,
propose, implement, and critique; the human owns scope, acceptance, priority,
release assignment (#188), merge, and release (#185). Capability selection is a
quality/latency lever only and moves none of those.

## Decomposed backlog (dispositioned)

| Work | Disposition |
| --- | --- |
| **#206** — validate as independent parallel review roles | **Backlog** — adopt only after it is built behind a flag and *measured against the baseline*; strongest precedent (validate already composes native reviews) but must beat 3/4 with an acceptable cost/latency trade. |
| Shape evidence/critique crew (the highest-opportunity group) | **Backlog** — larger than #206; needs its own scoped issue + baseline comparison before adoption. |
| Capability-selection wiring (`model.*` prefs + observability, ADR-0024) | **Backlog / blocked** — build only once a slice needs it; no infrastructure before an adopted consumer (ADR-0024). |

None is assigned to a shipping milestone: each is gated on a measured
improvement over the baseline, per #198.

## Go / no-go

**Go — research/architecture only.** ADR-0023 and ADR-0024 are Accepted; the
baseline is recorded as research evidence; #206 and the other slices are
backlogged pending a measured win. No README/roadmap/doc claims new orchestration
capability. The next milestone that adopts a slice will carry its own final
release gate that verifies the behavior end to end.
