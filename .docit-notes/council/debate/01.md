## Co-signed Nominations (Strong Weight)

All of these block or directly weaken the first-10-seconds promise.

### N00-1 — Resolve the MIT license overclaim (LICENSE vs manifests) — **CO-SIGN as P1**

**Why:** The README badge is visible above the fold. A reader who sees "license: MIT" in the hero and then hits the LICENSE file gets a trust-break at moment one. This is the single highest-risk accuracy gap. The hero cannot be honest-hype if the badge is false.

**Addition:** If the fix is to adopt MIT formally, the README badge becomes a genuine differentiator ("MIT licensed, commercially portable"). If the fix is to remove the badge and add an "All Rights Reserved" line, that's fine too — but the current state is the worst option: a false signal in the highest-visibility position. The issue is P1, but I'll note that I'm agnostic on which resolution wins — either is better than the current contradiction.

**Ground truth anchor:** `00-ground-truth.md` §"Accuracy flags" (license mismatch verified); `01-hero.md` §"Claims & Citations" item 8 already cites this caveat.

## Counter-Frames (Reframing to Sharpen Priority)

### N02-4 — `/spark:plan` GitHub Issue Creation Not Shipped in v0.2

**Current framing:** The quickstart "instructs a newcomer to run `/spark:plan` and expect 'Spark will decompose it into 2–5 GitHub issues.'"

**Counter-frame:** The Adopter is flagging a roadmap/feature-promise mismatch in the quickstart, which is correct. But the hero layer (README) does not make this promise. The README hero hook says "Install it once and every project gets the same versioned lifecycle—Ideate → Plan → Generate → Solve → Ship." It does not say "the Plan step creates GitHub issues." The hero is safe; the quickstart may be over-promising. This should be an Adopter-to-Coach issue (revise the quickstart), not a hero-layer issue.

**Recommendation:** Admit the issue, but note that the hero layer (my domain) is clear on this. The over-promise is in the Quickstart, not the hero. Assign the fix downstream.

### N06-C — Create `docs/tutorials/set-up-a-new-project.md` (Tutorial 1) — **REFRAME from P1 to P2 (medium)**

**Current priority:** P1 (High — blocks the "start from nothing" learner path)

The hero promises "Install it once and every project gets the same versioned lifecycle." It does not frame Spark as a first-timer's onboarding system. **Recommendation:** Admit the issue, but reframe as P2 (valuable for adoption, not critical for hero honesty). The hero does not promise a tutorial.
