### ADMIT — strong endorsements

**N00-1 / N01-2 / N03-2 / N04-1 / N05-3 / N09-3 / N10-4 — License mismatch (MIT vs. TBD)**

Co-sign at P1 across all personas who nominated it. The Amplifier has direct skin
in this game: every piece of launch copy in `11-launch.md` (tweet thread, HN blurb,
Reddit post) carries the license caveat explicitly because distributing launch copy

legal risk, not just a doc gap. The HN and Reddit posts state: "License: MIT
declared in the manifest; `LICENSE` file says 'TBD' — do not redistribute until
resolved." Those caveats are honest, but they are not a substitute for fixing the
root cause. No launch copy can drop this caveat until the `LICENSE` file is
resolved. This is the single hardest blocker from the Amplifier's perspective.
**Keep at P1.** The fix is a one-time author decision plus three file edits — the
cost of not doing it is discrediting every link the launch copy generates.

### CONTEST — insufficient merit or out-of-scope for Issues

**N02-3 — GitHub CLI (`gh`) prerequisite as a P1 launch blocker**

Contest the P1 priority; propose downgrade to P3. The `gh` CLI is a system-level
dependency that every GitHub-integrated developer already has (or knowingly lacks).
Flagging it as a P1 adoption blocker elevates a common prerequisite to a crisis.
The launch copy does not promise `gh` is unnecessary. The README can add a
prerequisites line cheaply. **Downgrade to P3.** This is a docs-polish item, not a
blocker that should delay the launch.

**N02-4 — `/spark:plan` does not create GitHub issues in v0.2**

Contest the framing, not the fact. The nomination is accurate: v0.3 is when
Plan ↔ GitHub integration ships. But the launch copy does not claim `/spark:plan`
auto-creates GitHub issues. The tweet thread, HN post, and Reddit post describe
Plan as "decompose into GitHub issues" — which is what the skill does (it outputs
structured issue drafts; the creation step is not claimed as mechanical). The
nomination conflates the skill's advisory output with an unshipped mechanical
integration. **This is a README/quickstart accuracy issue, not a launch-copy issue.
Reframe to P2 (clarify plan skill output in README/quickstart) and remove the
"P1 launch blocker" classification.** The launch copy is already honest about this.

**N04-4 — Document a breaking-change policy for pre-1.0**

Contest at P3 level, not admission. This is a legitimate documentation gap but it
is not launch-blocking and it has no bearing on the accuracy of any published claim.
The Evaluator's own framing ("P3 — pre-1.0 norm, not a blocker") is correct.
**Admit at P3; Amplifier has no objection but no stake in priority.** This does not
affect launch copy.

**N02-6 — `spark doctor` CI output schema for scripting**

Contest the P2 priority; propose downgrade to P3. The output contract for scripting
is a developer-experience enhancement, not a first-win blocker. The issue is
legitimate but far downstream of any launch concern. No launch copy claims `spark
doctor` is CI-ready or machine-parseable. **P3.**

## Strongest Positions

1. **The license issue is a P1 hard blocker for launch distribution.** Not a
   documentation gap — an active legal overclaim that every launched link exposes.
   Every other persona who nominated it is correct. The Amplifier's contribution:
   the launch copy cannot drop its license caveat until the `LICENSE` file is
   resolved. Until then, every piece of launch copy must carry the explicit warning.

2. **`codify` missing from README and CHANGELOG is a P1 launch blocker for the
   tweet thread / HN post / Reddit post.** The headline claim has no front-door
   confirmation. This is unique to the Amplifier's domain: other personas see it as
   a changelog or README accuracy issue; the Amplifier sees it as "the lede of my
   launch copy points at a feature the repo does not confirm." Distribution should
   wait until `codify` appears in both the README and the `[Unreleased]` changelog.

3. **Downgrade the GIF and lifecycle diagram from P1 to P2.** These are strong
   "want before launch" items, not blockers. The launch copy works without them.
   Filing them as P1 would stall launch over assets that are improvements, not
   corrections.

4. **Merge the overlapping nominations:** `spark doctor` output strings (two issues),
   `philosophy.md` (three issues), and skill layout spec (three issues) should each
   collapse to one tracked issue. The Council's signal is muddied when three personas
   file the same gap under three issue numbers.
