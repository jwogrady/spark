### On N00-1 / N01-2 / N03-2 / N04-1 / N05-3 / N09-3 / N10-4 / N11-1 — License mismatch (P1)

**CO-SIGN, with a P1 hold from the Contributor perspective.**

The license issue surfaces nine times across nine personas. That convergence is
itself evidence: it is the highest-signal issue in the entire council. The
Contributor's stake is concrete, not hypothetical. My note (`07-contributing.md`
§"Attribution policy") currently reads "this is a single-author project; attribution
is `jwogrady`." That is correct. But a contributor reading `CONTRIBUTING.md` who
then clicks the MIT badge and reads the `LICENSE` file will face an irreconcilable
contradiction: the badge says "MIT — freely usable"; the `LICENSE` file says "TBD —
copyright belongs to the author." There is no safe reading. A contributor cannot
know whether submitting a PR gives the project a right to distribute their code,
or whether they are contributing to a proprietary tool. This blocks external
contribution even more directly than it blocks adoption.

The fix is binary and author-decided: adopt MIT (add the standard SPDX text) or
update the manifest and badge to "All Rights Reserved." Neither requires a debate.
The Amplifier, Evaluator, Skeptic, Cartographer, Believer, Skimmer, Discoverer,
and Returning User all name this P1. I add my vote. Admitted, P1.

### On N07-1 / N06-B / N05-5 / N08-5 — Conflicting optional skill layout specs (P1/P2)

**CO-SIGN as P1. The Contributor's perspective adds weight the other personas
do not have.**

I nominated this myself (N07-1). I co-sign 06-B, 05-5, and 08-5 as raising the
same root issue from different angles. The convergence confirms scope.

The Contributor's position is the sharpest: the optional layout spec is not a
documentation gap — it is a contradiction in two authoritative source files. A
contributor who reads both `CONTRIBUTING.md` (`references/`, `agents/`) and
`skills/write-a-skill/SKILL.md` (`REFERENCE.md`, `EXAMPLES.md`, `scripts/`) will
produce a skill that conforms to one spec and violates the other. `spark doctor`
validates required frontmatter but does not enforce optional layout, so neither
spec wins at validation time. The broken symmetry means two contributors following
the "correct" guidance will produce inconsistent outputs.

Coach (06) rated this BLOCKING for the `write-a-skill` how-to (N06-B). Visual
Storyteller (08) rated it BLOCKING for the skill-anatomy diagram (N08-5). Believer
(05) flagged it as undermining the "additive by design" principle. The Contributor
adds: it also breaks the `spark new-skill` scaffold — `cmd_new_skill` creates a
minimal `SKILL.md`, but the author's next action (add an optional file) has no
correct answer.

The fix requires one decision (the canonical spec is whichever is most consistent
with actual skills in the repo), one source update, and then `docs/reference/skill-layout.md`
as the single authoritative reference. I recommend an ADR (ADR-0004) to record why
one spec won — consistent with the existing ADR-0001–0003 series.

Admitted, P1. I contest any downgrade to P2: this blocks the most important
contribution path (skill authorship) at its first optional-layout decision.
