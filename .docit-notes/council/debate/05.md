# Issue Council — Debate Positions from Persona 05 (Believer)

> Author: jwogrady
> Phase: 4 — Issue Council: Debate
> Persona: Believer (philosophy and motivation)

The Believer's stake: every nomination is evaluated through one lens — does it
serve or undermine the project's ability to stand behind its own principles?
The sixth principle ("honest attribution, honest hype") is the contract the
philosophy doc signs on behalf of the whole project. Anything that fractures
that contract is not a polish gap; it is a doctrine failure.

---

## License: the honest-hype contract's most visible failure

**Positions on: N00-1 (00), N01-2 (01), N03-2 (03), N04-1 (04), N05-3 (05),
N09-3 (09), N10-4 (10), NOM-11-1 (11)**

**CO-SIGN — elevate all to P1. Merge into one issue.**

Eight personas nominated this independently. That convergence is itself
evidence of severity. The Believer's specific position:

The philosophy doc's sixth principle is "honest attribution, honest hype —
claims travel only as far as the evidence beneath them." If `docs/explanation/philosophy.md`
ships while the README still displays an MIT badge backed by a "License TBD"
file, the project will demonstrate, on its most visible surface, that its
honest-hype contract is aspirational. That is precisely what the principle
refuses to accept. This is not legal caution — it is a doctrine failure.

The Believer endorses 04's language as the floor: "No enforceable open-source
license is in place." The fix is binary and cheap: either add the proper MIT
license text to `LICENSE`, or remove the MIT badge from the README and manifest.
Either choice is honest. The current state is not.

**Priority: P1. Must be resolved before `docs/explanation/philosophy.md` ships.
The philosophy cannot argue for honest-hype while the repo actively overclaims.**

## Canonical skill layout spec

**Positions on: N05-5 (05), N06-B (06), N07-1 (07), N08-5 (08)**

**CO-SIGN N05-5 / N06-B / N07-1 / N08-5. Merge all four into one issue. P1.**

Four personas identified the same root cause independently: two conflicting
optional skill layout specs in the same repo. The Believer's doctrine stake:
Principle 3 ("additive by design") asserts that every new skill extends Spark
cleanly. That principle is actively undermined when the extension path itself
is ambiguous. A contributor who finds two authoritative-looking files that
disagree on directory names cannot follow the principle, even if they want to.
This is a doctrine contradiction, not just a docs gap.

The Believer endorses 06's framing: the fix is a decision (pick the canonical
spec), a source-file update (fix the losing file), and a `docs/reference/skill-layout.md`
that is the single authoritative spec. An ADR is warranted — this is the same
class of decision as ADR-0001 through ADR-0003.

**All four nominations are the same issue. File one, close the duplicates.**

## README install block and marketplace caveat

**Positions on: N01-4 (01), N02-2 (02), N03-1 (03), N11-4 (11)**

**CO-SIGN all four. Merge into one issue. P1.**

The install block is the first action the README asks a user to take. Every
honest-hype note produced by this crew flags the marketplace listing as
unverified end-to-end (a confirmed ROADMAP open item). The README is the only
public-facing surface without the caveat. The Believer's position: the install
block is the most trust-critical paragraph in the README, and it currently
overclaims. This is not a polish gap — it is the same class of problem as the
license badge, applied to the user's first concrete action.

The fix is one qualifying sentence and a fallback instruction (Git URL install
path). It takes minutes. It prevents a broken first experience that would
undermine the "honest hype" principle at the exact moment a new user acts on
the documentation.

## `spark doctor` output format

**Positions on: N02-1 (02), N00-4 (00)**

**CO-SIGN. P2 — not P1.**

The Believer agrees the honest-hype contract requires that any quoted CLI
output match what the command actually produces. Citing a "16 skills / 19 agents
verified" summary line or an "OK" string that does not exist is an honesty
violation. Ground truth clearly describes the real output format
(`Healthy — 0 errors, N warning(s)`). Any doc that quotes a different string
must be corrected before ship.

**CONTEST 02's P1 classification.** The quickstart does not fall apart if we
simply quote the correct output format. This is a text correction across a
bounded set of docs — not a pipeline-blocker. P2 is appropriate: fix before
launch, but not a prerequisite for the philosophy doc or the license fix.

**Merge N00-4 and N02-1 into one editorial pass issue.**

### Set-up tutorial (N05-6 / N06-C): CO-SIGN P2

The Believer nominated this. The philosophy argues Spark makes "the right
thing easy." The setup skills (`bootstrap`, `connect`, `install-git-hooks`,
`doctor`) are the entry ramp, and they have no tutorial. The `build-your-first-project.md`

### `commit.md` how-to / ship.md mode-bleed (N06-D): CO-SIGN P2

This is a real Diátaxis violation — two discrete lifecycle stages blended in
one guide. The fix is well-scoped and the Believer does not contest P2.

Cannot be written accurately until the layout spec is resolved. The dependency
must be tracked. File it, link it to the layout spec issue.

### Branch naming convention (N07-3): CO-SIGN P3

Real gap, low friction to fix. Principle 3 ("additive by design") requires
that contributors know how to extend cleanly. Branch naming is part of that
extension path.

### Demo GIF and Mermaid lifecycle diagram (N08-1, N08-2): NUANCED

**N08-1 (demo GIF) — CO-SIGN.** Ground truth confirms `spark doctor` is real and
syntax-checked. The GIF is honest-hype *proof*, not marketing spin. The honest-hype
contract is strongest when it includes observable evidence. P1 is defensible for
a launch context; the Believer will not contest 08's P1 call, but notes this
requires author action outside the docit scope.

**N08-2 (Mermaid lifecycle diagram) — CO-SIGN P1.** The diagram resolves the
confirmed first-user confusion: stage is "Generate," command is `/spark:build`.
The philosophy argues the lifecycle is the core product; it should be scannable
in five seconds. A diagram that clarifies a real naming confusion earns P1.

### ASCII component map (N08-3): CO-SIGN P2

"Additive by design" is Principle 3. The ASCII map makes that principle
visible in the hero area. Verified, ready-to-paste per Phase 3. P2 is correct.

**CO-SIGN. P3.**

The `install-git-hooks` refusal-to-overwrite behavior is correct and verified.
The Believer co-signs the need for a documented coexistence pattern. Principle 1
