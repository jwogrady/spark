## Believer's reasoning notes (key positions)

**License cluster (P1):** The philosophy's sixth principle is honest attribution and
honest hype. The MIT badge overclaim is the most visible violation of that principle in
the repo. The philosophy cannot ship while the project actively contradicts the doctrine
it argues for. Hard P1; merge all nominations.

**`docs/explanation/philosophy.md` (P1):** This is the Believer's primary deliverable
for the run. It is drafted, cross-evaluated, and revised. Without a shipped, navigable
file it has no addressable home. Absorbs N03-3 (positioning doc tree) and N06-G
(cross-link wiring).

**`enforcement-model.md` (P2, not P1):** I agree with the 05-debate note: the philosophy
can ship with Principle 1 citing the real hooks (`guard-bash.sh`, `commit-msg`,
`pre-commit`) and a forward-reference to the rationale doc. It does not need to wait.
Downgrade from 06's BLOCKING claim.

**`authorship-crews.md` (P2):** Mode-correct linking is a real concern but not a launch
blocker. The philosophy can carry a "see also" link with the note that the doc is
forthcoming. P2; merge with N10-5.

**Canonical skill layout (P1):** Two conflicting specs in the same repo for the same
surface is a real integrity issue. It blocks the `write-a-skill` how-to and the
anatomy diagram. Merge all four nominations; rate P1.

**N02-4 (`/spark:plan` GitHub issues, P2):** This is a shipped-vs-roadmap honesty gap
inside the quickstart — it belongs in scope because it violates the honest-hype contract
the Believer owns. The quickstart must not assert mechanical GitHub issue creation in
v0.2. However it is not a legal risk or a broken install step, so P2 not P1.

- N04-2 (CI workflow): out of docit's shipping scope; a valid backlog item but not a
  documentation gap.
- N11-3 (`launch-copy.md`): internal docit output, not a repo documentation gap;
