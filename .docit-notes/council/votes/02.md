## Voting Rationale

### Critical Path (P1 — must resolve before v0.2 launch)

These are honesty-hype and install-path blockers. A newcomer discovers them in the first 30 seconds after installing. They directly undermine trust and credibility.

- **MIT license mismatch** (N00-1, N01-2, N03-2, N04-1, N05-3, N09-3, N10-4, N11-1): All admit as P1. This is the single highest-trust risk in the repo. The manifest declares MIT, the README badge says MIT, but the LICENSE file says "TBD." This is not a documentation tweak; it is a legal overclaim that contradicts at first touch.
  
- **Marketplace install caveat missing from README** (N01-4, N02-2, N03-1, N11-4): Admit as P1. The Phase 3 hero note and quickstart both carry this caveat ("from a local clone or Git URL; marketplace listing coming in v0.3"), but the README install block never got updated. A newcomer blindly copies the install command without knowing it is an unverified end-to-end path.
  
- **`spark doctor` output format overclaimed** (N00-4, N02-1): Admit as P1. Multiple drafts (including my quickstart) describe output ("16 skills verified / 19 agents") that does not exist in ground truth. This violates the honest-hype contract — when the newcomer runs the command, they see different output and lose trust immediately.
  
- **codify scratch-dir claim false** (N00-6): Admit as P1. The Changelog draft asserted codify "coordinates through `.docit-notes/`" which is false — codify uses `.codify-notes/` and is deliberately separate. This misrepresents the architecture in published docs.
  
- **Hero tagline never shipped** (N01-1): Admit as P1. The revised tagline from Phase 3 cross-eval ("Turn raw project intent into durable GitHub artifacts — in one portable toolkit") is more concrete than the current README intro, but was never integrated. First 10 seconds matter.
  
- **GitHub auth prerequisite hidden** (N02-3): Admit as P1. The promised "complete Ideate → Ship cycle in one session" requires `gh auth login` which is never mentioned upfront. A newcomer hits the final step and fails silently.

### Important (P2 — before declaring v0.2 complete)

These are credibility gaps and contributor clarity issues. They do not block first-win, but they undermine sustained adoption and team onboarding.

- **Philosophy and positioning docs missing** (N03-3, N05-1, N05-2, N05-4): Admit as P2. The principle layer ("why Spark takes the stances it does") and the honest comparison ("vs. alternatives") are in docit notes but not shipped to public docs. A skeptical reader has no entry point for "should I even use this?"
  
- **Canonical skill layout spec conflict** (N05-5, N06-2, N07-1): Admit as P2. Two sources specify different optional directory structures (`references/` vs `REFERENCE.md`; `agents/` vs `EXAMPLES.md`). Contributors cannot onboard until this is resolved.
  
- **Setup tutorial for inception path** (N05-6, N06-3): Admit as P2 (not P1). The gap is real — a user starting a new project from Spark seed needs bootstrap/connect/hooks guidance. But the plugin-install path (my domain) does not require this. Reframe as "blocks inception path, not plugin-install path."
  
- **Enforcement-model and authorship-crews explanation docs** (N05-2, N06-1, N06-5): Admit as P2. Diátaxis mode requires these explanation-tier docs to justify the mechanical enforcement and the multi-persona crew design. They are not first-win blockers but they complete the honest-hype story.
  
- **CHANGELOG entries missing codify and review** (N04-3, N09-1, N11-2): Admit as P2. These are shipped features but undocumented in release notes. A user who upgrades sees new skills appear with no explanation.

### Deferred (P2 post-launch nice-to-haves)

These are marketing, visual, and discoverability assets. They improve the web-based README experience and community visibility, but do not block install or first-win for a CLI user.

- **Visual assets** (N08-1, N08-2, N08-3, N08-4, N10-1, N10-2, N10-3): Admit as P2 (not P1). GIFs, diagrams, social-preview images, GitHub topics, and awesome-list submissions are valuable for web discovery but not for someone running `spark doctor` in a terminal. A newcomer does not need a GIF to verify the command works — they ran it and saw the output live.
  
- **Crew discoverability** (N10-5): Admit as P2. The multi-persona design (docit 13, codify 6) is architecturally novel, but it is not critical for first-win. Sustained engagement and advanced users care about this; it belongs in post-launch docs.

### Rejected

- **N02-4 (`/spark:plan` GitHub integration)**: Out. This is not a quickstart blocker — it is a feature-expectation mismatch that belongs in v0.3 planning, not Issue Council. The skill exists in v0.2 and generates drafts; it just does not create mechanical GitHub issues yet. A newcomer can still complete the Ideate → Ship cycle and learn the lifecycle. If we admit this, we are saying "a newcomer cannot succeed without this feature," which is not true.

## Key Decisions for the Editor

1. **Consolidate the license cluster**: Eight separate nominations for one binary decision. Merge into a single P1 issue with downstream edits (README badge, manifest, CHANGELOG caveat, launch-copy caveat) as a checklist.

2. **README must be updated from Phase 3 revisions**: Hero tagline and marketplace caveat both exist in the revision history but never landed in the live README. This is an editorial gap, not a missing-content gap.

3. **Newcomer-facing honesty is non-negotiable**: MIT license mismatch, marketplace install caveat, `spark doctor` output format, and GitHub auth prerequisite all violate the honest-hype contract at first touch. All must be resolved before public launch.

4. **Diátaxis gaps are real but post-launch**: Philosophy, enforcement-model, authorship-crews, and skill-layout spec are important for credibility and contributor onboarding, but they can ship in a follow-up PR if v0.2 launch is time-critical. Do not block on them if the critical path is otherwise clear.

5. **Visual assets improve marketing, not functionality**: GIFs, diagrams, and social-preview images are valuable for web discoverability. A CLI user does not need them to succeed. Treat as P2 and consider them post-launch if v0.2 timeline is tight.
