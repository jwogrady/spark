## N00-1 — Resolve the MIT license overclaim (LICENSE vs manifests)

**Priority: P1**

**Case:** `.claude-plugin/plugin.json` declares `"license": "MIT"` and the README
carries an MIT badge, but the actual `LICENSE` file reads "License TBD. Copyright
belongs to the author." The repo claims a license it has not adopted. This is the
single highest trust risk in the project: anyone installing the plugin sees MIT
in the manifest while the legal text grants nothing of the kind. Fix is a binary
choice — either add the real MIT text to `LICENSE`, or drop the MIT claim from
`plugin.json` and the README until a license is chosen. Until resolved, docs must
not advertise MIT.

**Provenance:** Ground truth "Accuracy flags" (license mismatch, verified by
reading `LICENSE` and `.claude-plugin/plugin.json`); reinforced in
`feedback/from-00-to-04.md` (Trust persona led with this; I endorsed it).

## N00-3 — Correct the hook file-layout in any component/architecture diagram

**Priority: P2**

**Case:** The Visuals draft's component-map ASCII (a) repeats the `list-skills`
omission and (b) groups `guard-bash.sh`, `commit-msg`, and `pre-commit` under a
single `hooks/` label. In reality `guard-bash.sh` lives in `hooks/` while

where enforcement lives. Any architecture visual that ships must match the real
tree. The docs-tree visual has a parallel error (ADRs/architecture shown nested
under `explanation/` when they are top-level siblings under `docs/`).

**Provenance:** `feedback/from-00-to-08.md` (both diagram corrections); ground
truth Enforcement section (`hooks/guard-bash.sh` vs `scripts/hooks/commit-msg`)
and Docs section (`docs/adr/`, `docs/architecture/` are top-level).

## N00-4 — Stop docs from putting an "OK"/tally string in `spark doctor`'s mouth

**Priority: P2**

**Case:** Multiple drafts described `spark doctor` output that does not exist:
the Changelog draft said it "prints OK"; the Quickstart draft implied a
"16 skills / 19 agents verified" summary line. Verified by reading `bin/spark`:
doctor emits a green `✓ <name>` per skill and per agent, then a final
`Healthy — 0 errors, N warning(s)` line. There is no "OK" string and no count
tally. Any doc, quickstart, or screenshot caption that quotes doctor output must
quote the real strings, or it will be falsified the moment a user runs the
command. Worth a single tracked issue so every persona's copy is corrected
consistently.

**Provenance:** `feedback/from-00-to-02.md` (item 1) and
`feedback/from-00-to-09.md` (item 4); ground truth CLI section (`cmd_doctor`
behavior).

## N00-5 — Pin volatile facts to durable references (version, counts, hashes, tag)

**Priority: P2**

**Case:** Phase 2 surfaced a cluster of falsifiable numeric/version errors across
drafts: "v0.1 is a solo tool" (repo is v0.2.0), "13 merged PRs" (git log shows 5
`Merge pull request` commits; #13 is a PR *number*, not a count), "13 commits
ahead" (`git rev-list v0.2.0..HEAD --count` = 15), and a wrong v0.2.0 hash
(`e013d6b` vs the real `e4082cb`). Each is individually small but together they
show a pattern: drafts cite volatile values that rot. The durable fix is an
editorial rule — cite the tag name (`v0.2.0`) not the hash, cite functions
(`cmd_doctor`) not line numbers, and avoid exact commit/PR counts in prose. This
issue tracks adopting that convention and correcting the current instances.

**Provenance:** `feedback/from-00-to-03.md` (version), `from-00-to-04.md` (PR
count / date span), `from-00-to-07.md` (line-number citations), `from-00-to-09.md`
(commit count + hash). Ground truth Plugin packaging (`"version": "0.2.0"`).

## N00-6 — Correct codify's scratch-dir claim: `.codify-notes/`, not `.docit-notes/`

**Priority: P1**

**Case:** The Changelog draft asserted that codify "coordinates through
`.docit-notes/` (shared with docit)." This is false and is the biggest accuracy
defect found across the whole team. `skills/codify/SKILL.md` uses
**`.codify-notes/`** and explicitly keeps it out of the repo; docit uses
`.docit-notes/`. They are deliberately separate scratch directories for two
separate crews (docit = 13 outward personas, codify = 6 inward agents). Conflating
them misrepresents the architecture in published docs and in any migration guide.
Every instance of "codify shares `.docit-notes/`" must be struck before ship.

**Provenance:** `feedback/from-00-to-09.md` (item 1, verified against
`skills/codify/SKILL.md`); ground truth (docit/codify are distinct crews; docit
coordinates through `.docit-notes/`).
