### 4. License mismatch creates discoverable friction (P2 — accuracy/legal trust)

**Title:** Resolve LICENSE file vs. plugin.json vs. README MIT claim

**Case:** The repo's discoverability promise (GitHub description, README) states "MIT license pending" or declares MIT, but the `LICENSE` file reads "License TBD. Copyright belongs to the author." Developers clicking through to verify the license encounter a contradiction, reducing trust. The contradiction is flagged in 00-ground-truth.md "Accuracy flags" and exposed in all downstream positioning (01-hero.md, 03-positioning.md, 04-trust.md). Until resolved (either adopt MIT formally with boilerplate header or clarify alternative), callers cannot legally fork or redistribute. From a discoverability perspective, an unresolved license is a red flag that blocks enterprise adoption.

**Provenance:** 00-ground-truth.md "Accuracy flags" section: "plugin.json declares `"license": "MIT"` and README badge says MIT, but LICENSE file contains only 'License TBD.'"; verified by reading `LICENSE`, `.claude-plugin/plugin.json`, and `README.md`.

**Priority:** P2 — medium urgency. Does not block use, but blocks redistribution and raises red flags for institutional adopters. Resolution needed before marketing push or awesome-list submission (nominators in Issue Council may contest inclusion on unlicensed software).

### 5. Docit and codify crew discoverability is weak (P2 — architectural novelty underexposed)

**Title:** Create discoverable landing pages for docit and codify multi-agent orchestration pattern

**Case:** The 13-agent docit crew and 6-agent codify crew are architectural novelties (multiple personas coordinating through shared `.docit-notes/`, not a single prompt; tiered models and scoped tools per agent). But they live buried in SKILL.md frontmatter and are mentioned only in 00-ground-truth.md and awesome-lists (awesome-multi-agent-systems). A developer interested in agent orchestration patterns, multi-persona crews, or tool orchestration will not find Spark in a targeted search. The "honest-hype contract" requires every keyword to trace to a capability; currently, "multi-agent" is discoverable but "docit crew architecture" is not. No how-to, no reference, no explanation doc exists yet (08-diataxis.md flags docit/codify how-tos and authorship-crews.md explanation as gaps). These gaps reduce the repo's reach in the agent-orchestration community.

**Provenance:** 00-ground-truth.md "Multi-persona authorship crews" section; 06-diataxis.md "Mode 2 — How-to guides" gap items (no docit/codify how-to); 06-diataxis.md "Mode 4 — Explanation" gap items (no authorship-crews.md explanation doc); 10-discoverability.md keyword 8 ("Multi-agent documentation") and awesome-list target 4 (Awesome Multi-Agent Systems).

**Priority:** P2 — medium discovery impact. Valuable for agent-focused developers, but not on the beginner path. Blocked by 06-diataxis.md resolution (is the canonical explanation for crew design going in authorship-crews.md or will it live in AGENTS.md?).
