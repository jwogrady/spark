## Nomination 06-A — Create `docs/explanation/enforcement-model.md`

**Priority: P1 (Blocking — philosophy prerequisite)**

**Case:**
The mechanical-enforcement differentiator (PreToolUse guard, `commit-msg`, `pre-commit`) is explicitly called out in `00-ground-truth.md` as a genuine differentiator, and `docs/PHILOSOPHY.md` principle 1 ("enforcement over aspiration") depends on it. No explanation doc currently exists that addresses *why* mechanical enforcement was chosen over advisory rules. ADR-0003 covers zero-dependency Bash but does not explain the enforcement-as-policy decision. Without `enforcement-model.md`, when `docs/PHILOSOPHY.md` ships, principle 1 will have no supporting rationale document — the philosophy will assert a principle it cannot link to without creating a Diátaxis mode violation (explanation should link to explanation, not to reference or how-to). This issue must be resolved before `docs/PHILOSOPHY.md` can ship without an orphaned claim.

**Provenance:**
- `06-diataxis.md` §Mode 4 Gaps, item "No `docs/explanation/enforcement-model.md`"

## Nomination 06-B — Resolve canonical skill layout spec and create `docs/reference/skill-layout.md`

**Priority: P1 (Blocking — `write-a-skill` how-to and agent-frontmatter reference cannot ship until resolved)**

**Case:**
Two conflicting optional-structure specs exist in the same repo for the same surface (skill directories). `CONTRIBUTING.md` §"Proposing a skill" specifies optional subdirs as `references/` and `agents/`; `skills/write-a-skill/SKILL.md` specifies `REFERENCE.md`, `EXAMPLES.md`, `scripts/`. A plugin author reading one spec and then the other gets contradictory guidance on how to lay out a skill. The downstream effect is hard: neither `docs/how-to/write-a-skill.md` nor `docs/reference/agent-frontmatter.md` can be written accurately until the canonical layout is decided. This is a code/spec debt masquerading as a docs gap — the fix requires a decision in the source files, then a `docs/reference/skill-layout.md` that is the single authoritative spec, cross-referenced from both `CONTRIBUTING.md` and `skills/write-a-skill/SKILL.md`.

**Provenance:**
- `06-diataxis.md` §Mode 3 Gaps, item "Canonical skill layout spec needed (HIGH — BLOCKING)"
- `06-diataxis.md` Cross-eval feedback §from-07 (Contributor) Item 1 (RESOLVED)
- `07-contributing.md` (cross-eval source) — two conflicting layout specs
- `00-ground-truth.md` §Lifecycle skills — `write-a-skill` skill exists at `skills/write-a-skill/SKILL.md`

## Nomination 06-C — Create `docs/tutorials/set-up-a-new-project.md` (Tutorial 1)

**Priority: P1 (High — blocks the "start from nothing" learner path)**

**Case:**
The current tutorial set has one entry: `docs/tutorials/build-your-first-project.md`, which walks through the full Ideate→Ship lifecycle. It is Tutorial 2; Tutorial 1 does not exist. A reader who arrives at Spark with a blank laptop and zero prior context has no guided lesson to complete before `build-your-first-project.md`. The setup skills (`bootstrap`, `connect`, `install-git-hooks`, `spark doctor`) are available (`00-ground-truth.md` §Setup/inception skills and §CLI) but there is no tutorial that takes a beginner by the hand through `bootstrap` → `connect` → `install-git-hooks` → `doctor` to a verified "clean" success state. The `build-your-first-project.md` tutorial links to `how-to/install.md` for prerequisites but that is a task guide, not a learning lesson — it assumes the reader already knows *why* these steps matter. Without Tutorial 1, the learner path is broken at its first step.

**Provenance:**
- `06-diataxis.md` §Mode 1 Gaps, item "No tutorial for setup skills"
- `06-diataxis.md` Cross-eval feedback §from-02 (Adopter) Item 3 (RESOLVED)
- `00-ground-truth.md` §Setup/inception skills — `bootstrap`, `connect`, `fork-init` skills verified

## Nomination 06-D — Create `docs/how-to/commit.md` and fix mode bleed in `ship.md`

**Priority: P1 (High — quickstart sends users to `/spark:commit` with no task guide; `ship.md` blurs two stages)**

**Case:**
`commit` is a discrete Stage 5a skill (`skills/commit/SKILL.md`, lifecycle stage "Stage 5a"; source: `00-ground-truth.md` §Lifecycle skills). `docs/how-to/ship.md` currently absorbs both the `/spark:commit` phase (steps 1-4) and the `/spark:ship` phase (steps 5-7) in one guide — verified by reading `docs/how-to/ship.md` in Phase 3. The Adopter note (`02-quickstart.md`) sends readers to `/spark:commit` without a dedicated task guide to land on. Blending two distinct stage-5 skills in one guide violates the Diátaxis how-to requirement that each guide address one specific goal. The fix has two parts: (1) create `docs/how-to/commit.md` covering Stage 5a alone; (2) revise `docs/how-to/ship.md` to cover Stage 5b alone and link to `commit.md` for Stage 5a context.

**Provenance:**
- `06-diataxis.md` §Mode 2 Gaps, item "No `commit` how-to"
- `06-diataxis.md` Cross-eval feedback §from-02 (Adopter) Item 1 (RESOLVED)
- `00-ground-truth.md` §Lifecycle skills — `commit` is Stage 5a, `ship` is Stage 5b, both verified as distinct skills
- Verified by reading `docs/how-to/ship.md` (Phase 3): covers both stages in one file

## Nomination 06-E — Create `docs/explanation/authorship-crews.md`

**Priority: P2 (High — required for mode-correct linking from `docs/PHILOSOPHY.md`)**

**Case:**
The multi-persona subagent design (`docit` 13 agents, `codify` 6 agents) is an architecturally significant feature verified in `00-ground-truth.md`. `docs/PHILOSOPHY.md` principle 6 ("honest attribution, honest hype") names the docit crew as the enforcement mechanism for the honest-hype contract. No explanation doc addresses *why* the crew architecture was chosen (multiple specialist personas vs. a single-prompt approach), *how* the coordination-through-shared-notes design works, or *what* the design principles of both crews are. Without this doc, `docs/PHILOSOPHY.md` principle 6 must either link to a how-to (task-oriented, wrong mode) or be left with no supporting doc at all. Diátaxis requires explanation to link to explanation; this is a blocking mode violation once the philosophy ships.
