## Nomination 1 — No `spark doctor` demo GIF exists (missing must-ship asset)

**Title:** Create and publish `spark doctor` terminal demo GIF

**Case:** The README currently contains zero captured terminal output. `spark doctor` is the single command that proves the tool is mechanical, not aspirational — it validates manifests, hooks, skills, and agents and returns a clean exit code. Without a real GIF, prospective users have no visual confidence signal that the tool is live and working. Phase 3 acknowledged this gap and deferred it to the author with explicit capture instructions, but the asset does not exist at the repo root, under `docs/assets/`, or anywhere in `.github/`. The gap is now a launch blocker for the README because the Quickstart section lands a user at `spark doctor` with no visual proof it does anything. The fix is a one-time capture using `vhs` or `asciinema`, saved to `docs/assets/spark-doctor-demo.gif`, and embedded in the README Quickstart section with the alt text already specified in `08-visuals.md`.

**Provenance:** Raised as a must-ship gap in `08-visuals.md` Asset 3 (Phase 1 and Phase 3). Confirmed absent by `ls docs/assets/` (directory does not exist). Confirmed by `02-quickstart.md` cross-eval (from-02-to-08.md): "Without the GIF, the Quickstart section will lack visual confidence." Ground-truth anchor: `00-ground-truth.md` §"The `spark` CLI" — `spark doctor` is a real, verified, syntax-checked subcommand returning non-zero on error.

**Proposed priority:** P1 — this is the only visual proof-of-life for the CLI; the Quickstart section is incomplete without it.

## Nomination 5 — Skill directory anatomy tree blocked by conflicting specs in `CONTRIBUTING.md` vs `write-a-skill/SKILL.md`

**Title:** Resolve canonical optional skill layout spec before authoring skill-anatomy diagram

**Case:** The skill directory anatomy tree (Asset 8 in `08-visuals.md`) cannot be finalized or shipped because two files in the same repo specify conflicting optional directory names for a skill. `CONTRIBUTING.md` §"Proposing a skill" lists `references/` and `agents/` as optional subdirectories. `skills/write-a-skill/SKILL.md` lists `REFERENCE.md`, `EXAMPLES.md`, and `scripts/`. These are not the same. A diagram built on either spec would be factually wrong against the other. The visual is currently blocked and will remain blocked until the canonical spec is decided and codified. The diagram itself is ready to draw — the blocker is upstream authoring and policy work. This nomination requests that the inconsistency be tracked and resolved as its own GitHub issue, unblocking both this visual and the `write-a-skill` how-to (which Persona 07 identified as separately blocked for the same reason in from-07-to-06.md).

**Provenance:** Raised as a blocked asset in `08-visuals.md` Asset 8. Root cause identified in `from-07-to-08.md` Issue 2 ("Caveat for 08: skill layout spec is currently inconsistent"). Independently confirmed in `from-07-to-06.md` Issue 1 (rated "High — blocks writing the how-to"). Ground-truth anchor: `00-ground-truth.md` does not resolve the conflict (it only cites `write-a-skill/SKILL.md` for "When to Split").

**Proposed priority:** P2 — the conflict blocks at least two artifacts (the anatomy diagram and the `write-a-skill` how-to) and creates contributor confusion; should be resolved in the next docs maintenance pass.
