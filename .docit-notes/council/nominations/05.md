## Nomination 2 — `docs/explanation/enforcement-model.md` does not exist, blocking philosophy

**Scoped title:** Write `docs/explanation/enforcement-model.md` — rationale for mechanical enforcement over advisory rules

**Case:** Philosophy principle 1 ("enforcement over aspiration") states that Spark's guardrails are enforced by code, not by suggestion. This is the project's core design argument — the thing that separates Spark from a CLAUDE.md with aspirations. That principle is compelling and grounded in real features (PreToolUse guard, `commit-msg` hook, `pre-commit` hook), but it lands without explanation in the philosophy doc because the supporting rationale document does not exist. The `docs/explanation/` tree currently has `sdlc-doctrine.md`, `scope-and-upstream.md`, and `why-a-plugin.md` — all of which explain *what* was decided, not *why mechanical enforcement* was chosen as the governing principle. ADR-0003 covers zero-dependency Bash; it does not explain the enforcement-as-policy decision. Without `enforcement-model.md`, the philosophy reads as assertion rather than argument. Persona 06 elevated this to "BLOCKING — philosophy prerequisite" in their priority gaps table, and the Believer concurred in cross-eval feedback to 06.

**Provenance:** `05-philosophy.md` §Principle 1 (enforcement over aspiration, cites `hooks/guard-bash.sh`, `scripts/hooks/commit-msg`, `pre-commit`); `06-diataxis.md` §Mode 4 gaps ("`docs/explanation/enforcement-model.md` — BLOCKING — philosophy prerequisite"); `00-ground-truth.md` §Genuine differentiators ("Guardrails are mechanical, not advisory"); `00-ground-truth.md` §Docs (no `enforcement-model.md` listed).

**Proposed priority:** P1

## Nomination 3 — License status blocks redistribution and undermines the honest-hype contract

**Scoped title:** Resolve the license mismatch: adopt MIT formally or update the manifest and badge to "All Rights Reserved"

**Case:** The philosophy doc's sixth principle is "honest attribution, honest hype" — every claim traces to evidence. The project currently fails its own principle on the most visible surface: `plugin.json` declares `"license": "MIT"` and the README badge says MIT, but the `LICENSE` file reads "License TBD. Copyright belongs to the author." This is not a cosmetic inconsistency. Shipping a philosophy doc that says "claims travel only as far as the evidence beneath them" on a project that overclaims MIT license rights is a direct contradiction of the doctrine the Believer owns. Persona 04 (Evaluator) rated this the single highest-trust risk in the repo and hardened the language to: "No enforceable open-source license is in place. Do not incorporate Spark into a project with legal review requirements until a license file is formally adopted." Persona 03 (Skeptic) added it to the "What Spark concedes" section. The fix is one decision and three file edits — either adopt MIT (add a proper MIT `LICENSE` file) or downgrade the manifest and badge to reflect the actual status. Either resolution is honest; the current state is not.

**Provenance:** `00-ground-truth.md` §Accuracy flags ("License mismatch — `plugin.json` declares MIT; `LICENSE` file reads 'License TBD'"); `04-trust.md` §License status ("No enforceable open-source license is in place"); `03-positioning.md` §"What Spark concedes" (license concession bullet); `05-philosophy.md` §Principle 6 (honest attribution).

**Proposed priority:** P1

## Nomination 5 — Canonical skill optional-layout spec is unresolved, blocking contributor onboarding

**Scoped title:** Decide and document the canonical optional skill layout; reconcile `CONTRIBUTING.md` vs. `write-a-skill/SKILL.md`

**Case:** Two authoritative sources in the repo specify different optional directory structures for skills. `CONTRIBUTING.md` §"Proposing a skill" names `references/` and `agents/` as the optional subdirs. `skills/write-a-skill/SKILL.md` names `REFERENCE.md`, `EXAMPLES.md`, and `scripts/`. A contributor scaffolding a new skill today has two conflicting specs and no way to know which is canonical. This blocks `docs/how-to/write-a-skill.md` (cannot be written accurately until the spec is settled) and creates noise in `spark doctor` (if it ever validates optional layout). Persona 07 (Contributor) raised this as a blocking inconsistency. Persona 06 (Coach) confirmed it and rated it High in their priority gaps table. The Believer's stake: the philosophy principle of "additive by design" means every new skill should extend Spark cleanly — that promise is undermined when the extension path itself is ambiguous. Fix: pick one canonical layout, update the losing source, and document the decision (an ADR would be appropriate given the existing ADR-0001–0003 series).

**Provenance:** `07-contributing.md` §Cross-eval from 06 ("Two conflicting optional skill layout specs"); `06-diataxis.md` §Reference gaps ("Canonical skill layout spec needed — BLOCKING `write-a-skill` how-to"); `00-ground-truth.md` §CLI `doctor` (validates skill frontmatter); `CLAUDE.md` §"Skill Authoring" (authoritative source cites `CONTRIBUTING.md` only).

**Proposed priority:** P2

## Nomination 6 — No "start from nothing" tutorial; setup skills (bootstrap, connect, hooks, doctor) are undocumented for new users

**Scoped title:** Write `docs/tutorials/set-up-a-new-project.md` — Tutorial 1 (prerequisite path: bootstrap → connect → install-git-hooks → doctor)

**Case:** The philosophy argues that Spark makes "the right thing easy." For a new user, the right thing starts before any ideate/plan/build cycle — it starts with project setup: `bootstrap`, `connect`, `install-git-hooks`, `doctor`. None of these setup skills have a tutorial. The only tutorial (`docs/tutorials/build-your-first-project.md`) drops straight into the Ideate → Ship lifecycle, presupposing an already-configured project. A motivated new developer who follows the install steps and immediately runs `/spark:ideate` has no guided path through the setup layer. The setup skills are real and verified (`00-ground-truth.md` §Setup/inception skills). The Tutorial 1 gap is not a nice-to-have — it is the entry ramp for every new user. Persona 06 (Coach) rated this High and recommended repositioning: set-up tutorial becomes Tutorial 1, `build-your-first-project.md` becomes Tutorial 2.

**Provenance:** `06-diataxis.md` §Mode 1 gaps ("No tutorial for setup skills — HIGH — blocks 'start from nothing' path"); `00-ground-truth.md` §Setup/inception skills (bootstrap, connect, fork-init, claude-md, agents-md, write-a-skill all verified); `00-ground-truth.md` §Docs (only one tutorial listed).

**Proposed priority:** P2
